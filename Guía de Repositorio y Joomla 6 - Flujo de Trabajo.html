1. La Fase Joomla (Gestor de Contenidos)

Todo cambio nace aquí. Joomla es el alojamiento principal para los recursos multimedia (imágenes, PDFs).

⚠️

Requisito de Aprobación Previa

Antes de realizar cualquier cambio definitivo en el código de Joomla, este debe ser previamente editado, revisado y aprobado mediante un Pull Request en el repositorio de GitHub (este proceso se explica más adelante).

🌐

¿Qué define a un Micrositio?

Entendiendo la arquitectura base para organizar nuestras carpetas.

En el contexto de la plataforma web gestionada con Joomla, la estructura visual (el header con el menú de navegación) no siempre representa la estructura técnica. Para organizar correctamente nuestro repositorio en GitHub, debemos identificar qué secciones son Micrositios.

Un Micrositio se define como una instalación o instancia aislada de Joomla. Esto significa que contiene sus propios artículos (páginas web), su propia base de datos y su propia gestión de recursos, los cuales no están mezclados con el portal principal u otros micrositios.

💡 El acceso al Administrador

La forma para confirmar si una sección es un micrositio independiente es mediante la URL del administrador:

  1. Ve a la URL de la sección en cuestión (ej. https://minas.medellin.unal.edu.co/vicedecanaturadeinvestigacion/index.php/investigacion-fm/grupos-de-investigacion).
  2. Quita index.php y todo lo que esté después.
  3. Agrega administrator al final de la URL.
  4. El link debería quedar de la siguiente manera: https://minas.medellin.unal.edu.co/vicedecanaturadeinvestigacion/administrator
  5. Presiona Enter.
Resultado: Si la página te solicita un Usuario y Contraseña de Joomla específico para esa ruta, estás frente a un Micrositio.

Regla de Repositorio: Cada Micrositio identificado mediante este método debe tener su propia carpeta principal en la raíz de nuestro repositorio en GitHub (ej. micrositio-facultad-de-minas, micrositio-cdi).

🗜️

Optimización de Assets

Antes de subir cualquier imagen a Joomla, es obligatorio realizar un proceso de compresión para optimizar los tiempos de carga. Esto para garantizar el cumplimiento del límite establecido, según el cual las imágenes y archivos, como los PDFs, no deben superar los 50 MB.

  • ✔️ Utilizar herramientas como TinyPNG a la cual pueden acceder por https://tinyjpg.com/ para reducir el peso sin pérdida de calidad visual.
  • ✔️ Se recomienda, siempre que sea posible, utilizar el formato .webp para las imágenes. Si se requiere convertir el formato, puede hacerse fácilmente mediante la herramienta disponible en el siguiente enlace: https://squoosh.app/.

📂 Estructura de las Carpetas en Joomla

Para mantener el orden, la primera capa siempre será el Año Actual, seguida del micrositio y subcarpetas creadas a demanda (solo cuando se necesiten).

GIT

2. La Fase GitHub (Repositorio de Código)

Una vez el contenido está publicado en Joomla, usamos GitHub estrictamente como bóveda de respaldo del código HTML/CSS/JS. Las carpetas en GitHub seguirán una estructura similar a la usada en Joomla, sin embargo solo vamos a usar como carpeta raíz el nombre del micrositio, es decir, no usaremos como primera capa la carpeta de año actual.

📂 Estructura de las Carpetas en GitHub

La carpeta raíz será directamente el micrositio. No se deben guardar archivos distintos al código (.html, .css, .js) en GitHub, ya que los archivos multimedia e imágenes ya están centralizados en Joomla.

📁 Repositorio GitHub
📁 micrositio-facultad-de-minas <-- Carpeta Raíz Principal
📁 comunicaciones <-- Subcarpeta (Igual a Joomla)
📄 convocatorias.html <-- Solo archivos de código
📄 eventos-vie.html
📁 micrositio-vie
... carpetas internas
🔤

Kebab-case y Prefijos

Todo en minúsculas y separado por guiones. Los micrositios (carpetas principales) deben llevar el prefijo.

✔️ micrositio-bienestar/
✔️ historia-facultad.html
❌ Micrositio Bienestar
⏳

Cero Versionado de Archivos

Git guarda el historial automáticamente. No se debe usar años o "versiones" en el nombre de los archivos HTML. Sobreescribimos el mismo archivo siempre.

✔️ decano.html
❌ decano-2026.html
❌ prueba-final.html
🛡️

El Escudo: .gitignore

Regla: No guardamos Assets en GitHub. Ya viven en Joomla. El archivo .gitignore bloquea automáticamente subidas por error.

*.webp
*.png / *.jpg
*.pdf
*.docx

El Idioma del Repositorio

Para mantener un estándar internacional y facilitar la lectura del historial, todos los mensajes de commit deben redactarse en Inglés y ser descriptivos (explicar qué y por qué se hizo).

Ejemplo de Commit Ideal "Add link to graduates list for collective graduation ceremony 2026-1S"
Ejemplos Incorrectos (Pobres) ❌ "Update html" ❌ "cambios en graduados"
